# Tenant access and support recovery — 2026-09-12

Baseline: main a1a155d93ef7897437aeb02fe43ed982d531b07e. Owner reports the Super Admin sidebar in /rmprime/admin plus denied tenant access. Read-only audit confirms an active non-owner, non-Super Admin tenant Admin with confirmed email, no ban/deletion and exactly one active membership. This does not prove successful password authentication. No credential or session was extracted from the owner's browser.

The shell previously queried a global cached role independently of the requested route, while tenant middleware correctly rejected Super Admin. The authenticated parent now validates account/route compatibility before child loading and shell mounting. The shell role comes from this boundary, never the old cache. Failures in role lookup fail closed. Account transitions clear query/tenant caches. Login distinguishes credential failure from post-authentication routing failure.

Frozen support contract: POST accepts only caseId, email, requestId and confirmed=true. Actor/session come from verified server claims. Require global Super Admin, password authentication within 15 minutes, a live session and AAL2 if MFA is enrolled. The case must be open, category access, have a requester reference and a customer tenant. Resolve only that tenant's active non-owner Admin whose confirmed email exactly matches the support request; reject Super Admin, banned/deleted accounts and inactive companies. This is a support exception, not tenant-user CRUD or impersonation.

Two service-only RPCs reuse platform_support_cases and append audit_log. Because audit_log is writable by tenant admins under existing policies, it cannot be the authority for rate limiting or idempotency. A new private requests ledger, accessible only inside the two definer functions, owns those controls; no existing RLS is changed. Advisory locks serialize per actor and target. Reserve before external email delivery: same requestId never sends twice, target cooldown five minutes, operator limit ten/hour. Crash/timeout means unknown, never automatic resend. Provider acceptance is not inbox delivery. No tokens/passwords/email are stored in audit or returned by the endpoint. The only delivery call is resetPasswordForEmail with a fixed realone.com.br/reset-password destination. The recipient defines the password using Supabase's verified recovery session. Neither the support operator nor Codex sets it.

No existing table/RLS/CMS/tenant/membership/owner/user/DNS/Cloudflare modifications. Add one private requests ledger with RLS and no direct grants, two narrowly granted functions and application code. Existing account recovery preserves server password policies. SQL must pass isolated PostgreSQL tests and production signature/ACL readback before publication. End-to-end inbox receipt and actual password change require the recipient's interaction, and must not be claimed from mocked delivery or a successful API response.
