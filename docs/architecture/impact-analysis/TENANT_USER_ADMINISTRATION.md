# Tenant user administration corrective — 2026-09-13

Baseline main: 1b28669da62aff4d2a38a348f65289930aafc1d9. The owner approved the interface and requests three behavioral corrections: platform identities are not tenant staff; tenant permissions must be customizable; Admin registers/configures a new user before activation email.

## Observed causes
The live tenant has a historical owner row carrying a global Super Admin role plus one operational Admin. listTenantMemberships returns both using service credentials and Auth email lookups. Global identity exclusion must happen before serialization/Auth lookup and also cover direct membership/profile/team reads. Do not transfer ownership, delete the global account or rewrite historical ownership to conceal this error.
System RBAC templates are immutable by design, but no copy/customize action exists. The live assert_tenant_access_manager treats the operational Admin as delegated; invite_tenant_member still requires owner and contains an obsolete impersonation branch. Existing server route denial does not justify retaining it in this mutation.

## Frozen contract
Reuse tenant_members, user_profiles, rbac_profiles and rbac_permissions. Add tenant-local display name and activation delivery state to membership. Admin supplies name, email, non-owner role and selected profiles; passwords are never accepted. The server resolves tenant/actor from session, rejects platform identities, checks access-manager authority/profile visibility/seats, creates an unconfirmed Auth identity without email only if absent, and atomically persists the pending membership/name/profiles through an orchestration RPC calling canonical invitation/profile primitives. Only after success does it send the provider activation email to an unconfirmed identity. Existing confirmed identities receive a sign-in link, without resetting or overwriting their password. Provider failure is recorded separately from saved registration; resend is explicit and rate limited. Failed configuration sends no email; an unconfirmed Auth identity created before a failed database transaction may remain without access and is reused on retry, never blindly deleted.

Copying a global profile produces one editable canonical profile per tenant/template, under the tenant lock and existing permission grant authority. The global template remains unchanged; users are assigned the customized copy explicitly. The same matrix is available from user configuration and profile management. No separate permission storage or user-specific parallel authorization system.

Active tenant Admin is a first-class access manager within its own tenant. Super Admin and impersonation origins are rejected by access/invitation primitives. A restrictive directory policy excludes platform identities for authenticated direct reads. Server service-role read paths additionally filter before returning identity fields. Historical owner references are preserved and never displayed as operational staff. This is authorization hardening, not an email blacklist.

## Gates
Use isolated PostgreSQL tests for role/membership authority, platform exclusion, tenant A/B separation, immutable templates, copy idempotency, configured profiles before activation, transaction rollback and anonymous grants. Actual-component tests cover new-user fields/profiles, editable-copy transition and honest delivery errors. Mock all Auth/email effects. Apply only the audited schema/function delta after tests; no production user creation or commercial permission assignment during deployment. Preserve approved visual identity, DNS/Cloudflare/domains, CMS and 0028 backlog. Record exact source/deployment identity and public smoke; do not claim an authenticated production business journey without that session.
